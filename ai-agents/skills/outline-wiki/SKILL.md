# Outline Wiki

Outline 内の既存文書を根拠に、日本語で調査・編集する。利用可能な Outline MCP を優先し、ツール名や仕様を推測しない。

## 原則

- 目的、読者、対象コレクション、書き込み可否を把握する。
- 検索結果のタイトルだけで判断せず、本文、更新日時、権限・公開状態を確認する。
- 回答には参照文書名と Outline のリンクを添え、推測と未確認事項を明記する。

## MCP の使い方

1. 利用可能な Outline MCP ツールと入力スキーマを確認する。
2. 一覧・検索・取得などの読み取り操作で対象と ID を確定する。ID を推測しない。
3. ページネーションは必要な範囲を取得し、部分結果や権限不足を明示する。
4. 書き込み前に対象の最新状態を取得し、操作と影響を確認する。
5. 書き込み後に再取得して、本文、配置、公開状態などを検証する。

Outline MCP が使えない、接続できない、または必要な操作が提供されていない場合は作業を中止し、理由と未実施範囲を伝える。Web UI や REST API で代替しない。

## 読む・答える

- 日本語・英語の関連語や固有名詞で検索し、関連度の高い文書を必要な範囲だけ読む。
- 複数文書を比較し、矛盾は更新日時だけで解消せず、所有者や一次資料も考慮する。
- 結論を先に書き、その根拠を文書リンク付きで示す。確認できない内容を補完しない。

## 文書を作る・更新する

標準配置は次の3段構造とする。

```text
コレクション
└── カテゴリ文書（説明と索引）
    └── 個別文書
```

- 作成前に文書ツリーと類似記事を調べ、既存カテゴリを親にして重複を避ける。
- 適切なカテゴリがなければ配置案を示す。依頼範囲外のカテゴリを無断で新設しない。
- 更新時は現行本文を取得し、構成、リンク、注意事項を保ちながら目的に必要な最小範囲を編集する。
- Markdown は短い導入、結論、見出し、手順、必要なリンクで構成し、読者の次の行動を明確にする。
- 外部 Markdown の移行では、相対リンク、画像、表、コードブロックが壊れないか先に確認する。

## 変更の境界

- 明示的な反映依頼がなければ、本文案と配置案の提示までにする。
- 通常の作成・更新は、対象、操作、変更要点を確定してから反映する。
- 意味や方針の大幅な変更は、差分の要点を反映前に示す。
- 移動、アーカイブ、削除、一括変更、公開、権限変更は、対象・件数・影響を示して明示承認を得る。
- コレクションをまたぐ移動は、変更前後の実効権限を比較する。確認できなければ実行しない。
- 統合元はすぐ削除せず、統合先への案内を置いてからアーカイブする。削除は別途承認を得る。

## コレクションを再編する

新設・分割・統合・大規模整理の場合だけ、作業前に [コレクション設計と再編](references/collection-design.md) を最後まで読む。

包括的な「整理して」は棚卸しと提案までとする。承認後は変更マップを作り、少数で検証してから段階的に反映する。

## 完了報告

日本語で次を簡潔に報告する。

- 実施した操作と対象文書へのリンク
- 再取得による検証結果
- 未実施・未確認事項

下書きのみなら、Outline へ反映していないことを明記する。
