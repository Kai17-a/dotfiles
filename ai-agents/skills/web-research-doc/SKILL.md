# Web Research Doc

Web上の情報を調査し、レビュー可能な粒度の日本語ドキュメントとして `docs/research/` 配下に作成する。

このSkillは調査・要約・ドキュメント化を対象とする。PoCの実装や動作検証そのものは対象外。

## 使用場面

次のような依頼で使用する。

- 「Kong AI Gateway について調べてまとめて」
- 「Semantic Cache プラグインの仕組みをドキュメント化して」
- GitHub Issue（Task/SubTask）の「概要」「仕組み」「できること」を埋めるための事前調査

## 手順

### 1. 調査スコープを確認する

着手前に次を明確にする。曖昧な場合はユーザーに確認する。

- 調査対象（製品名、プラグイン名、バージョンなど）
- 知りたい観点（例: 概要 / 仕組み / できること / 制約）
- 対応する既存のGitHub Issue番号（あれば）
- 成果物の想定利用先（社内説明資料の元ネタか、実装の設計資料かなど）

### 2. 一次情報を優先して収集する

情報源は次の優先順位で選ぶ。

1. 公式ドキュメント・公式リポジトリ（例: Kong公式ドキュメント、Kong Gatewayのplugin reference）
2. 公式ブログ・公式リリースノート
3. 信頼できる技術記事・カンファレンス発表
4. その他の二次情報（個人ブログなど）は補足情報として扱い、事実の裏付けには使わない

`WebSearch` で候補を洗い出し、`WebFetch` で一次情報のページ本文を取得して読む。検索結果のスニペットだけで内容を断定しない。

バージョン依存の情報（対応プラグイン、設定項目など）は、参照したドキュメントのバージョン・日付を控えておく。

### 3. 情報を整理する

収集した内容を次の観点で整理する。

- 概要（何のためのものか、位置づけ）
- 仕組み（内部動作、処理の流れ）
- できること（機能、対応範囲、設定項目）
- 制約・注意点（未対応事項、既知の制限）
- 不明点・要追加調査事項（調べても分からなかったこと。無理に埋めない）

推測で埋めない。出典から確認できなかったことは「不明点」として明示する。

### 4. ドキュメントを作成する

`docs/research/<対象を表すslug>.md` として保存する。例: `docs/research/kong-ai-gateway-semantic-cache.md`

テンプレート:

```markdown
# <調査対象名>

作成日: <YYYY-MM-DD>
関連Issue: #<番号>（あれば）

## 概要

<一文〜数文で要点>

## 仕組み

<内部動作・処理フローの説明>

## できること

- <機能1>
- <機能2>

## 制約・注意点

- <既知の制限や注意事項>

## 不明点・要追加調査事項

- <出典から確認できなかった点>

## 参考情報

- [<タイトル>](<URL>) - 参照日: <YYYY-MM-DD>
```

参考情報には、実際に内容を確認したURLのみを記載する。リンク切れや未確認のURLを推測で載せない。

### 5. 完了報告する

作成後、次をユーザーに報告する。

- 作成したドキュメントのパス
- 主要な参照元
- 「不明点・要追加調査事項」として残った項目（あれば）

コミットするかどうかはユーザーの指示に従う（このSkill単体では自動コミットしない）。
